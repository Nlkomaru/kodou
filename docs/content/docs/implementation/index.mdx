---
title: Bluetooth 心拍取得の実装
description: BLE Heart Rate Service からの心拍取得と、フロントエンドへの受け渡し
---

`iron-heart` の方針を参考に、BLE標準の Heart Rate Service を Tauri の Rust 側で扱います。
WebView から Web Bluetooth を直接使うのではなく、Rust 側でOSのBluetooth adapterに接続し、
React 側へイベントとして心拍データを流します。

## 1. デバイス検出

- Bluetooth adapter を取得する。
- BLE scan を開始する。
- Heart Rate Service (`0000180d-0000-1000-8000-00805f9b34fb`) をadvertiseしているデバイスだけを一覧に出す。
- UIではデバイス名、アドレス、RSSIを表示する。

## 2. 接続と通知購読

- 選択されたデバイスに接続する。
- GATT service/characteristic をdiscoverする。
- Heart Rate Measurement characteristic (`00002a37-0000-1000-8000-00805f9b34fb`) を探す。
- characteristic のnotificationをsubscribeする。
- Battery Level characteristic (`00002a19-0000-1000-8000-00805f9b34fb`) があれば、接続時と一定間隔で読む。

## 3. 心拍パケット解析

- 1バイト目のflagsで BPM が8-bitか16-bitかを判定する。
- sensor contact、energy expended、RR interval の有無をflagsから読む。
- RR interval は BLE spec に合わせて `raw / 1024 sec` としてmsへ変換する。
- 解析結果を `heart-rate-reading` イベントとしてfrontendへ送る。

## 4. UI反映

- `scan_heart_rate_monitors` command でデバイス一覧を取得する。
- `start_heart_rate_monitor` command で選択デバイスの購読を開始する。
- `heart-rate-status` イベントで接続状態を表示する。常設の表示はサイドバー、状態の変化は `useStatusToast`（sonner のトースト）で通知する。トーストは ID を固定しているため、状態が変わっても積み上がらず同じトーストが差し替わる。
- `heart-rate-reading` イベントでBPM、RR interval、battery、sensor contactを更新する。

## 5. 記録

デバイスへ接続すると、心拍データの記録が自動で始まります。記録するかどうかの設定はありません。

### 保存先とファイル名

アプリのデータディレクトリ配下 `recordings/` に、年月フォルダ + 日付 + 連番で保存します。

```text
recordings/
  2026-06/
    2026-06-01_1.parquet
    2026-06-01_2.parquet
    2026-06-02_1.parquet
```

- 接続するたびに新しいファイルを作り、同じ日の記録は連番（`_1`, `_2`, ...）で並べます。
- 日付は、利用者が探しやすいよう UTC ではなくローカル時刻で決めます（各行のタイムスタンプは UTC のエポックミリ秒）。

### 耐障害性（クラッシュ・電源断への備え）

Parquet はファイル末尾の footer（行グループの索引）が無いと読めません。footer は close 時にしか書かれないため、クラッシュ・強制終了・電源断・`pnpm dev` の再起動で記録が中断されると、それまでのデータがすべて読めなくなります。これを避けるため、記録中と確定後で形式を分けています。

- **記録中は `.arrow`（Arrow IPC stream 形式）へ書きます。** stream 形式は末尾に footer を持たず、追記のたびに読める状態が保たれるため、途中で切れても完全に書けたバッチは読み戻せます。
- **バッチ確定ごとに `fsync`（`sync_all`）します。** OS のバッファ止まりにせずディスクまで届かせることで、電源断でも直近のバッチまで守れます。心拍は約 1Hz・書き出しは約 1 分に 1 回なので、コストは無視できます。
- **接続を切る（正常終了）と `.arrow` を `.parquet` へ変換して確定します。** 変換後に `.arrow` は削除され、標準ツール（pandas / polars / DuckDB）で読める Parquet だけが残ります。
- **起動時に、前回中断されて残った `.arrow` を Parquet へ復旧変換します。** 変換に失敗したものは `.arrow` を残し、次回起動で再試行するため元データを失いません。この復旧は記録開始より前に行い、記録中の `.arrow` を誤って変換しないようにしています。

### 記録状態の通知

記録中かどうかと保存先を UI で確認できるように、記録の開始・終了をイベントで通知します。

- `recording-started` イベントで、書き込み中のファイル（記録中は `.arrow`）のパスを送る。
- `recording-stopped` イベントで、記録の終了を送る。
- React 側は `recordingPathAtom` にパスを保持し、履歴ページで「記録中」の行を示すために使う。

### 履歴一覧

履歴ページでは、保存済みの記録ファイルを新しい順に一覧表示します。

- `list_recordings` command で、`recordings/` 配下の `<年月日>_<連番>`（`.parquet` と記録中の `.arrow`）を走査して一覧を取得する。
- 一覧は日付ごとにまとめ、各行にファイル名・記録した時間帯（`22:03 - 22:41`）・ファイルサイズ・BPM の最小 / 平均 / 最大を表示する。
- 時間帯と BPM は 1 回読んで集計する。平均は行グループの統計に含まれないため、`timestamp_ms` と `bpm` の 2 列だけを射影して 1 パスで数えます。確定後の `.parquet` と記録中の `.arrow` の両方を集計でき、`.arrow` は途中で切れていても読めたバッチまでを数えます。
- 各行のタイムスタンプは UTC なので、時刻の表示形式（ローカル時刻・24 時間表記）はフロントエンド側で決める。Rust はエポックミリ秒のまま返します。
- 1 行も無いファイルは集計が `null` になる。その場合は時間帯の代わりに最終更新時刻を出す。記録中は `recordingPathAtom` のパスと一致する行に「記録中」バッジを出す。1 件の読み取りに失敗しても、一覧全体は表示できるようにしています。
- 各行の「フォルダで開く」ボタンから、`@tauri-apps/plugin-opener` の `revealItemInDir` で OS のファイルエクスプローラーを開く（ファイルが選択された状態になります）。
